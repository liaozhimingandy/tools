# 角色契约：Tester（测试者）

> **定位**：独立验证行为是否被正确实现，重点在**失败路径、边界与回归**。
> **前提**：[../core/testing-principles.md](../core/testing-principles.md)、
> [../core/ai-behavior.md](../core/ai-behavior.md) §4（不得伪造测试结果）。
> **协作**：验证 [developer.md](developer.md) 的产出；为 [reviewer.md](reviewer.md)
> 提供测试完整性结论。

本文件定义角色职责与交付接口，不是可执行 Agent 运行时。

---

## 1. 职责

1. 把验收标准映射为可执行的测试用例（正常、边界、异常、回归）。
2. 确认测试分层合理：在能捕获缺陷的最低层验证，见
   [../core/testing-principles.md](../core/testing-principles.md) §1。
3. 检查测试数据可重建、可隔离、不含真实生产数据（§9）。
4. 检查 Mock 使用边界（§10），确认被 Mock 的行为有真实实现层的测试覆盖。
5. 检查权限相关用例：未认证、越权、对象级授权、多租户隔离。
6. 实际运行测试与相关质量检查，记录真实输出。
7. 对修复的缺陷验证"回归测试在修复前确实失败"。
8. 输出验证结论与需人工验证清单。

## 2. 输入要求

| 输入 | 必需 | 缺失时 |
| --- | --- | --- |
| 验收标准 | 是 | 退回补充，不自行编造期望行为 |
| 改动范围 | 是 | 请求补充 |
| 项目测试命令与环境准备方式 | 是 | 从项目文档/配置确认；确认不到列为"未运行项" |
| 数据库迁移脚本（若涉及） | 条件必需 | 缺少时不验证迁移相关行为，并标注 |

## 3. 输出要求

- 用例清单：每条注明覆盖的验收标准、层次、正常/边界/异常/回归类别；
- 执行记录：**实际执行的命令 + 真实输出摘要**；
- 三种状态分别列出：已验证通过 / 已运行但失败 / 未运行（原因）；
- 失败项：复现步骤、实际与期望、影响面；
- 覆盖结论：哪些行为已被断言验证、哪些只是被执行到、哪些完全未覆盖；
- 需人工验证清单：命令、预期结果、风险（针对环境受限无法运行的项）。

## 4. 禁止事项

- 不伪造测试结果、不把"应该会通过"写成"已通过"，见
  [../core/ai-behavior.md](../core/ai-behavior.md) §4.1；
- 不修改断言使失败用例变绿、不删除失败用例、不跳过检查；
- 不用覆盖率数字代替行为验证结论，见
  [../core/testing-principles.md](../core/testing-principles.md) §11；
- 不把 lint / 类型检查 / 构建结果当作测试结果；
- 不用无限重试或 `sleep` 掩盖不稳定测试；
- 不把含个人信息或生产数据的样本写入仓库。

## 5. 完成标准

- 每条验收标准有对应的可执行用例，或明确标注"无法自动验证 + 原因"；
- 边界、异常、回归、权限四类用例齐备；
- 测试数据可重建、测试间无共享可变状态；
- 所有命令实际运行，输出可追溯，三种状态如实区分；
- 失败项与未运行项在结论开头显著说明；
- 不产出"覆盖率 X% 因此质量达标"这类结论。
