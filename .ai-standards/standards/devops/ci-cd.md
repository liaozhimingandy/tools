# CI/CD 规范

> **何时读**：新增或修改流水线、门禁、构建脚本、制品与发布流程时。
> **前提**：[../../core/testing-principles.md](../../core/testing-principles.md) §12（真实执行与汇报）、
> [../../core/security-principles.md](../../core/security-principles.md) §8、§12（密钥与依赖）。
> **红线**：发布、推送、删除远端资源等外部动作须获授权，见
> [../../core/ai-behavior.md](../../core/ai-behavior.md) §3.10。

---

## 1. 流水线可复现

- 流水线定义纳入版本管理；不在 UI 里手工改出"只有这次生效"的配置。
- 固定工具链版本（运行时、包管理器、构建镜像）；不使用漂浮的 `latest`。
- 依赖安装使用锁文件；缓存键包含锁文件哈希，避免"缓存命中但依赖已变"的假成功。
- 流水线步骤在本地也能以相同命令复现，便于排障。
- 不在构建脚本中依赖开发者本机路径、当前工作目录之外的文件或交互式输入。

## 2. 门禁分层

**规则**：越快的检查越靠前，失败即停，明确失败原因。

| 阶段 | 检查 | 失败处理 |
| --- | --- | --- |
| 静态 | 格式、lint、密钥扫描 | 立即失败，输出具体文件与规则 |
| 类型 | 类型检查（**指定正确的配置**） | 立即失败 |
| 测试 | 单元 → 集成 → API → 少量 E2E | 保留失败用例名称与日志 |
| 构建 | 产物构建、容器镜像构建 | 失败不发布 |
| 安全 | 依赖漏洞、镜像扫描（若有） | 按项目策略阻断或告警 |

- 门禁不得被"先跳过、以后补"绕过；临时跳过需有明确期限与责任人。
- 类型检查在 composite 项目引用结构中必须显式指定子配置，见
  [../languages/typescript.md](../languages/typescript.md) §1；
  根目录零输出不等于通过。
- **构建通过 ≠ 类型检查通过 ≠ 测试通过**：三者都是独立门禁。

## 3. 测试与环境

- 测试使用隔离的临时数据库/服务；用例自备数据并清理，见
  [../../core/testing-principles.md](../../core/testing-principles.md) §9。
- 不使用生产数据、生产凭据或生产环境跑测试。
- 不稳定的测试先修根因，不用无限重试或 `sleep` 掩盖；显式等待优于固定等待。
- E2E 只覆盖关键链路；失败保留截图/日志/请求 ID，且不含敏感数据。

## 4. 密钥与权限

- 密钥通过平台的 secret 机制注入，不写入流水线文件、日志或制品。
- 日志输出做脱敏；不在失败时打印整个环境变量集合。
- CI 使用的凭据按最小权限授予，且与生产凭据隔离，见
  [../../core/security-principles.md](../../core/security-principles.md) §2、§8。
- 来自 fork / 不可信来源的 PR 不获得 secret；不自动执行其未审查的脚本。
- 制品仓库的写权限单独控制，不复用构建账号的读权限。

## 5. 制品与版本

- 制品带唯一、可追溯的版本标识（提交 SHA / 版本号），不使用会被覆盖的 `latest` 作发布依据。
- 制品不可变；发现问题构建新版本，不原地替换已发布制品。
- 版本号规则见 [../../docs/versioning.md](../../docs/versioning.md)。
- 制品中包含的构建元数据（时间、提交、依赖清单）可查询，便于回溯。

## 6. 发布与回滚

- 发布步骤与回滚步骤成对定义；回滚必须演练过，而不是只在文档里写一句。
- 数据库迁移与代码发布解耦：先部署兼容版本 → 执行迁移 → 再清理，见
  [../backend/database.md](../backend/database.md)。
- 采用渐进发布（灰度/金丝雀/特性开关）时，明确观测指标与中止条件。
- 发布属于外部不可逆动作，需明确授权；失败时自动中止并保留现场信息。
- 发布后做冒烟验证，并如实记录通过/失败/未运行项，见
  [../../core/ai-behavior.md](../../core/ai-behavior.md) §6。

## 7. 可观测与维护

- 每步有清晰的开始/结束与耗时；失败信息指向具体命令与文件。
- 流水线脚本与项目代码同批次维护；不留下长期失效的"手工步骤"。
- 定期清理过期缓存与制品；不因缓存膨胀导致构建变慢或磁盘耗尽。
- 不在 CI 中执行与验证无关的动作（发送消息、修改外部系统），除非明确设计并有权限控制。

## 8. 验证清单

1. 在干净环境从头运行流水线，结果可复现；
2. 每道门禁失败时能给出可定位的错误；
3. 无明文密钥、日志已脱敏、PR 不获得 secret；
4. 制品版本唯一且不可变；
5. 回滚步骤已演练，含数据库迁移的兼容顺序；
6. 实际运行结果已记录，未运行项如实标注。
