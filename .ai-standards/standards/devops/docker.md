# Docker 与容器规范

> **何时读**：编写/修改 Dockerfile、compose、镜像构建、容器运行时配置时。
> **前提**：[../../core/engineering-principles.md](../../core/engineering-principles.md) §10（配置）、
> [../../core/security-principles.md](../../core/security-principles.md) §2、§8（最小权限、敏感配置）。

---

## 1. 基础镜像

- 使用项目既有、来源可信的基础镜像；版本用明确的 tag 或 digest，不用 `latest`。
- 优先精简镜像；区分构建阶段与运行阶段，用多阶段构建把编译器、构建工具留在构建层。
- 不擅自更换基础镜像发行版或包管理器，见
  [../../core/ai-behavior.md](../../core/ai-behavior.md) §3.2。
- 基础镜像变更需评估：glibc/musl 差异、时区与证书、用户权限、CVE 面。

## 2. 构建效率与可复现

- 按变更频率排序层：依赖清单先复制并安装，源码最后复制，充分利用缓存。
- 提供 `.dockerignore`，排除 `.git`、本地构建产物、密钥文件、测试数据与日志。
- 包安装锁定版本；不在构建期拉取"最新版"依赖，见
  [../../core/security-principles.md](../../core/security-principles.md) §12。
- 构建参数（`ARG`）不用于传递密钥；构建期需要的凭据使用受支持的 secret 机制。
- 同一份输入应产出可复现的镜像；避免在 Dockerfile 内使用当前时间、随机数或网络拉取未锁定资源。

## 3. 运行时权限

- **不以 root 运行**：创建非特权用户并 `USER` 切换；只授予实际需要的目录写权限。
- 不启用 `--privileged`，不挂载宿主机 Docker socket，除非有明确授权与替代方案评估。
- 容器文件系统尽量只读；需要写入的目录显式挂载卷并设置权限。
- 不设置 `setuid`/`setgid` 能力；不添加不必要的 Linux capabilities。
- 见 [../../core/security-principles.md](../../core/security-principles.md) §2。

## 4. 配置与密钥

- 配置通过环境变量/运行时注入；镜像内**不得**包含密钥、口令、私钥、`.env` 真实值。
- `ENV` 中不写敏感默认值；示例配置用明显无效的占位值。
- 区分构建期与运行期配置，不把生产地址编译进镜像。
- 日志输出到 stdout/stderr，由平台采集；不在容器内自行写日志文件并轮转。
- 见 [../../core/security-principles.md](../../core/security-principles.md) §8。

## 5. 健康检查与生命周期

- 提供 `HEALTHCHECK`（或编排层等价探针），检查的是"能否服务"而非"进程是否存在"。
- 启动探针、就绪探针、存活探针语义分开；失败阈值与超时明确。
- 应用正确处理 `SIGTERM`，在终止前完成在途请求与资源释放。
- 入口使用 exec 形式（`CMD ["..."]`）保证信号能传到主进程；不用 shell 形式包装。
- 不在容器里跑多个无监督的常驻进程。

## 6. 网络与数据

- 只暴露必需的端口；不把数据库、缓存、调试端口暴露到公网。
- 服务间通信使用内部网络与明确的名称；不依赖容器 IP。
- 持久化数据只放显式声明的卷；容器可随时被销毁重建。
- 有状态服务的启动顺序、迁移执行与回滚方式写清，见
  [../backend/database.md](../backend/database.md)。

## 7. 编排（compose / K8s 等）

- 资源限制（CPU/内存）与重启策略显式声明；不依赖默认无限资源。
- 敏感值走 secret 管理，不写进编排文件的明文环境变量。
- 开发与生产配置分离但共享基础定义，避免两份文件逐渐漂移。
- 不把"本地能跑"的 compose 直接当生产配置使用。

## 8. 验证清单

提交前确认：

1. 镜像实际构建成功并启动，健康检查通过；
2. 进程以非 root 运行，文件系统权限最小化；
3. `docker history` / 镜像层中无密钥与源码之外的敏感文件；
4. `.dockerignore` 生效，镜像体积合理；
5. `SIGTERM` 能优雅退出；
6. 配置全部来自运行时注入，生产地址未硬编码；
7. 构建、启动、冒烟检查命令已实际运行并记录结果。
