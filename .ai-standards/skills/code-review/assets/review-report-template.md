# 代码审查报告模板

> 每次 `code-review` 任务结束填写。问题清单可以为空，但 10 个维度的结论不能省。

| 元信息 | 内容 |
| --- | --- |
| 审查范围 | 〈diff 标识 / 文件列表 / 提交范围〉 |
| 关联需求 | 〈需求文档或验收标准标识；无则写「缺失」〉 |
| 日期 | 〈日期〉 |
| 审查者 | 〈角色〉 |

## 问题统计

| 项 | 数量 |
| --- | --- |
| 发现问题总数 | 〈N〉 |
| `CRITICAL` | 〈N〉 |
| `HIGH` | 〈N〉 |
| `MEDIUM` | 〈N〉 |
| `LOW` | 〈N〉 |
| `INFO` | 〈N〉 |

> 总数必须等于 5 级数量之和。

## 结论

**〈可合入 / 有条件合入 / 不可合入〉**

- 是否存在阻止合并的问题：〈是 / 否；是则列出 `CRITICAL` / `HIGH` 编号〉
- 判定理由：〈与下方问题列表一致〉
- 有条件合入时的条件：〈逐条，必须可执行〉
- 显式豁免：〈若存在 HIGH 但仍判定可合入，逐条写明豁免理由与记录人；否则写「无」〉

> 判定须与问题列表逻辑一致：存在 `CRITICAL` 不得判定可合入；
> `HIGH` 默认阻止合入，如需豁免必须显式记录。结论自相矛盾视为不合格。

## 问题清单（按严重程度排序）

| # | 严重程度 | 文件及代码位置 | 一句话标题 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 〈级别〉 | 〈路径:行号〉 | 〈标题〉 | 已确认 / 待确认 |

每条问题的完整 6 字段内容按 `assets/finding-template.md` 附在表后。
没有问题清单时写：「本次未发现需报告的问题」，不要编造 INFO/LOW 凑数。

## 验证状态

| 项 | 内容 |
| --- | --- |
| 实际运行的只读检查 | 〈命令 + 结果；无则写「未运行」〉 |
| 提供的验证结果 | 〈已提供 / 缺失〉 |
| 说明 | 〈验证结果缺失时不假定已通过〉 |

---

## 填写说明

- 问题清单可以为空；十个维度的结论与「已确认无问题的维度」不可省。
- 不以问题数量作为质量指标，不为凑数量虚构问题。
- 推测一律标注「待确认」并给出确认方法。
- 本报告是只读产物，不得在审查期间修改代码或测试断言。
