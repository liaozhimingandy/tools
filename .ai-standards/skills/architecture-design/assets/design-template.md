# 架构设计文档模板

> 用法：复制本结构填写。第 1 节必须基于代码事实；无法确认的写「待确认 + 怎么确认」。
> 本模板是设计，不是实现计划；不得包含代码片段或提交级任务拆分。

| 关联需求 | 〈需求文档标识〉 |
| 状态 | 草案 / 待确认 / 已确认 |

| 维度 | 方案 A（最小改动） | 方案 B（替代） |
| --- | --- | --- |
| 需求满足 | 〈说明〉 | 〈说明〉 |

## 7. 迁移 / 回滚 / 兼容方案

- 兼容窗口：〈旧代码读新数据、新代码读旧数据〉
- 迁移步骤：〈顺序，含前置检查〉
- 回填 / 双写策略：〈分批、可暂停、幂等〉
- 回滚：〈脚本级 + 数据级；不可逆项及补偿〉
- 验证：〈迁移前后对比方式〉
- 不涉及数据时写：「不涉及」，并说明依据。

## 填写说明

- 第 1 节每行都要有证据；没有证据的移入「待确认项」。
- 方案比较表 8 个维度不得留空，不适用的写「不适用 + 原因」。
- 涉及数据库结构变更时，第 7 节缺任一项都不得进入实施阶段。
