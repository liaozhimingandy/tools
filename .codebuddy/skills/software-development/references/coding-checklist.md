# 编码自检清单

> 由 `software-development` 步骤 5 按需加载。逐条勾选；不适用的写「不适用 + 原因」。

## 1. 范围与复用

- [ ] 每个改动文件都能回答「为什么在本次改动里」
- [ ] 已查找并复用项目内等价实现，未凭函数名猜测其行为
- [ ] 缺陷优先在原位置修复，未复制出一份「修正版」
- [ ] 无无关格式化、重命名、依赖升级 diff
- [ ] 未删除既有功能、未修改公共契约（或已获明确授权）

## 2. 命名与可读性

- [ ] 命名表达业务含义，与仓库既有风格与术语一致
- [ ] 无散落魔法值；有限取值集中定义
- [ ] 函数职责单一，控制流线性，嵌套不过深
- [ ] 注释解释「为什么」，公开接口有文档字符串

## 3. 类型与数据形状

- [ ] 公开函数有类型标注；无 `any` / 裸 `dict` 回避建模
- [ ] 区分「不存在」「为空」「未加载」
- [ ] 外部输入在边界校验：类型、范围、长度、格式、枚举、集合大小
- [ ] 校验失败返回一致、可机读的错误结构

## 4. 错误处理

- [ ] 捕获具体异常类型；无空捕获块；未吞掉异常
- [ ] 包装异常保留 cause；资源确定性释放
- [ ] 错误信息含上下文但不含堆栈、SQL、路径或敏感数据
- [ ] 重试仅用于瞬时故障，有次数上限与退避

## 5. 安全

- [ ] SQL 全部参数绑定；标识符来自白名单
- [ ] 无 `shell=True` / 拼接命令；无不可信数据进入 `innerHTML` 类接口
- [ ] 服务端完成对象级授权与多租户隔离；前端隐藏不算安全控制
- [ ] 日志已脱敏；无密钥、Token、完整请求体
- [ ] 外部 URL / 上传文件走白名单与服务端命名

## 6. 并发与外部调用

- [ ] 共享可变状态有明确同步策略或改为不可变
- [ ] 外部调用设置超时、响应上限、幂等键
- [ ] 无 `sleep` 作为同步手段、无无条件重试循环
- [ ] 时间使用统一时区与时钟来源

## 7. 可测试性

- [ ] 核心逻辑可在不启动服务/不连数据库的情况下测试
- [ ] 时钟、随机、网络、文件系统依赖通过注入控制
- [ ] 新增分支有对应断言（不是只被调用到）
- [ ] Mock 未绕过真实行为验证；被 Mock 的行为有集成层覆盖

## 8. 提交前清理

- [ ] 无未使用导入、变量、死分支
- [ ] 无调试输出、临时开关、硬编码环境值
- [ ] 无新增未授权依赖
- [ ] 相关文档（接口/配置/部署/README）已同步
- [ ] `git diff` 已逐文件复查

---

## 反模式

- 用 `// TODO 以后再处理` 把已知缺陷留在交付里；
- 为了让检查变绿而放宽 lint / 类型配置；
- 把「构建通过」当作「类型检查通过」或「测试通过」；
- 在根目录跑 composite 项目的类型检查却得到零输出就宣布无错误。
