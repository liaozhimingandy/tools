# 代码审查详细检查项

> 由 `code-review` 的 10 个维度按需加载。每个维度都要给出结论；
> 发现问题时按 `assets/finding-template.md` 记录。

## 1. 业务逻辑正确性

- 逐条对照需求与验收标准，检查是否遗漏、多做了什么、语义是否被改写；
- 边界条件（空/零/上限/重复/状态边界）是否符合规格；
- 默认值、取整、排序、时间单位、金额单位是否与既有约定一致；
- 是否有"顺带"改变既有行为而未说明。

## 2. 架构合理性

- 模块职责是否仍单一；是否出现"什么都放里面"的 utils；
- 依赖方向是否单向无环；是否绕过公开接口直接访问内部状态；
- 每份可写数据是否仍有唯一所有者；
- 是否存在只有一个实现的接口、只有一层转发的包装、循环依赖。

## 3. 安全风险

- 输入校验在服务端边界完成；对象级授权逐个资源判定；
- 认证与授权分离；未登录/过期/越权/跨租户场景；
- SQL 注入、命令注入、XSS、CSRF、SSRF、路径穿越；
- 密钥、口令、Token 未进代码/日志/URL；上传按内容校验并服务端命名；
- 新增依赖的来源、许可证与已知漏洞；多租户隔离在数据访问层强制；
- 错误信息不泄漏堆栈、SQL、内部路径或资源存在性以外的信息。

## 4. 数据库和事务风险

- 是否有迁移脚本、回滚路径、旧数据兼容与回填策略；
- 约束与索引是否匹配查询；是否引入 N+1、`SELECT *`、无界集合；
- 事务边界是否过宽/过短；失败后数据状态是否可解释；
- 并发写入是否有唯一约束或幂等键；是否依赖"先查再插"；
- 深分页排序是否有唯一键作为 tie-breaker。

## 5. 并发问题

- 共享可变状态是否有同步策略；是否引入竞态；
- 重复提交、乱序消息、迟到响应是否处理；
- 超时、重试上限、退避、幂等键是否显式；
- 异步任务失败后的补偿与可观测信号。

## 6. 性能问题

- 无界集合、全量加载、循环内 I/O 或 INFO 级日志；
- 同步阻塞调用出现在请求主链路；缓存一致性窗口；
- 大对象序列化、重复计算、缺失分页上限；
- 新增索引的写放大与建表锁影响（若适用）。

## 7. 错误处理

- 异常是否被吞掉；捕获后是否只打日志就继续；
- 失败后是否使用了未初始化/部分写入的数据；
- 错误信息是否含足够上下文且不含敏感数据；
- 资源是否确定性释放；重试是否只针对瞬时故障。

## 8. 向后兼容性

- 公开 API 签名、字段语义、状态码、错误码、事件格式；
- 数据结构与配置项的旧值能否被新代码读取；
- 部署方式、环境变量、迁移顺序是否变化；
- 旧客户端/下游消费者是否需要同步改动；是否有迁移步骤。

## 9. 测试完整性

- 正常、边界、异常、回归四类用例；
- 缺陷修复是否有"修复前失败"的回归用例；
- 权限用例：未认证、越权、对象级授权、跨租户；
- Mock 是否绕过了真实行为、被 Mock 的行为有无集成层覆盖；
- 是否有只调用不断言、靠覆盖率充数的测试。

## 10. 不必要的复杂度

- 未使用的参数、配置项、接口、分支；
- 为模式而模式：多余分层、只有一个消费者的事件/包装；
- 未授权的新依赖、为小功能引入的大库；
- 可用现有实现却另写一套。

---

## 严重程度判定

统一使用 5 级标准名称，不与其它名称混用。

| 级别 | 判定依据 | 对合入的影响 |
| --- | --- | --- |
| `CRITICAL` | 严重安全漏洞、重大数据损坏/丢失、服务不可用、系统级风险、破坏性契约变更未迁移、测试伪造 | 阻止合入 |
| `HIGH` | 重要功能错误、严重兼容性问题、边界或异常路径缺失、明显并发/性能风险 | 默认阻止合入，或需显式豁免并记录 |
| `MEDIUM` | 一般 Bug、明显边界问题、较大可维护性风险、测试缺口、错误信息不清 | 有条件合入（需登记修复） |
| `LOW` | 轻微问题、低风险改进建议、局部可读性瑕疵 | 不阻止合入 |
| `INFO` | 非缺陷性质的说明、优化建议、纯风格偏好 | 不影响合入 |

## 反模式

- 把「我不喜欢这种写法」写成 HIGH 及以上（纯风格应标 INFO）；
- 同一问题换三种说法充数；
- 因为测试通过就跳过安全与兼容性维度；
- 没有发现问题时编造几条 INFO/LOW 凑数；
- 把推测写成确定缺陷（应标「待确认」并给出确认方法）。

> 注：第 6 维度中的「INFO 级日志」指**日志级别**，与本节的审查严重程度分级无关。
