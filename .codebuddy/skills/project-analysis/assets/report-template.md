# 项目分析报告模板

> 用法：复制本结构生成报告。每个方括号字段都必须填写；不适用的写「不适用 + 原因」，
> 未确认的写「未确认 + 缺少什么 + 怎么确认」。不要删除章节。

## 1. 概览

| 项 | 内容 |
| --- | --- |
| 分析时间 | 〈日期〉 |
| 项目根目录 | 〈绝对路径或相对路径〉 |
| 根目录判定依据 | 〈例如存在 .git / pyproject.toml〉 |
| 项目目标 | 〈摘自入口文档；无文档写「未找到」〉 |
| 技术栈一览 | 〈语言 / 框架 / 主要库〉 |
| 分析范围与抽样依据 | 〈全量或抽样；抽样的范围与理由〉 |

## 2. 目录结构与关键文件

| 路径 | 用途 | 证据 |
| --- | --- | --- |
| 〈路径〉 | 〈用途〉 | 〈读到的文件/命令输出〉 |

## 3. 依赖与技术栈

| 依赖 | 声明版本 | 锁定版本 | 来源文件 |
| --- | --- | --- | --- |
| 〈名称〉 | 〈版本或「未声明」〉 | 〈版本或「未锁定」〉 | 〈路径〉 |

运行时版本、构建工具、容器与 CI 配置：〈逐项列出，无则写「无」〉

## 4. 模块边界与依赖方向

| 模块 | 一句话职责 | 公开接口 | 依赖方向 |
| --- | --- | --- | --- |
| 〈名称〉 | 〈职责〉 | 〈接口〉 | 〈依赖谁 / 被谁依赖〉 |

循环依赖：〈有 / 无 / 未确认，附路径〉
边界模糊处：〈路径 + 现象〉

## 5. 关键数据流与调用关系

用例：〈名称〉

```text
入口 → 校验点 → 转换 → 写入方 → 外部系统 → 响应
```

| 环节 | 位置 | 失败行为 | 证据 |
| --- | --- | --- | --- |
| 〈环节〉 | 〈路径〉 | 〈行为〉 | 〈路径〉 |

异步边界与补偿：〈说明或写「无」〉

## 6. 数据库结构

| 实体 / 表 | 关键字段 | 约束 / 索引 | 迁移方式 | 证据 |
| --- | --- | --- | --- | --- |
| 〈名称〉 | 〈字段〉 | 〈约束〉 | 〈方式〉 | 〈路径〉 |

租户 / 权限相关字段：〈说明或写「未发现」〉
无数据库时写：「无」，并说明对本次任务的影响。

## 7. 测试体系

| 项 | 内容 |
| --- | --- |
| 目录与框架 | 〈路径 / 框架〉 |
| 运行命令 | 〈命令，未找到写「未找到」〉 |
| 分层情况 | 〈单元 / 集成 / API / E2E〉 |
| CI 门禁 | 〈命令与位置〉 |
| 已覆盖的关键路径 | 〈列举〉 |
| 明显缺口 | 〈列举 + 证据〉 |

## 8. 技术债务与风险

| # | 证据（路径 + 现象） | 影响 | 建议 | 置信度 |
| --- | --- | --- | --- | --- |
| 1 | 〈证据〉 | 〈影响〉 | 〈可执行方向〉 | 已确认 / 待确认 |

**禁止**：在本节写「建议重写」「架构太乱」这类无证据结论。

## 9. 已确认事实 / 未确认事项 / 需用户澄清的问题

- 已确认事实：〈逐条，附来源〉
- 未确认事项：〈逐条：缺什么、怎么确认、不确认的后果〉
- 需用户澄清的问题：〈背景 + 选项 + 各自后果，问题必须可回答〉

## 10. 下一步建议

〈只读建议；说明可作为哪个 Skill 的输入；明确写出本次未发生任何写操作〉

---

## 填写说明

- 「证据」列不能为空：没有证据就把该行移入第 9 节的「未确认事项」。
- 报告服务于后续任务，不追求面面俱到；但第 9 节必须完整。
- 本报告是只读产物，不得在调研期间修改项目文件。
