# 边界与异常场景清单

> 由 `requirements-analysis` 步骤 3、4 按需加载。按「维度 → 边界 → 异常」逐项过一遍，
> 适用的写入需求文档，不适用的不用写理由。

## 1. 输入数据维度

| 维度 | 必查边界 | 常见异常 |
| --- | --- | --- |
| 数值 | 0、1、最大值、最大值 +1、负数、精度极限 | 溢出、非数字字符串、科学计数法 |
| 字符串 | 空串、仅空白、最小/最大长度、Unicode、特殊字符 | 编码不一致、超长截断、注入字符 |
| 集合 | 空、单元素、批量上限、超过上限、含重复项 | 部分成功、顺序不稳定、内存膨胀 |
| 枚举/状态 | 初始态、终态、非法转换、重复操作 | 状态机跳跃、幂等缺失 |
| 时间 | 时区、月末、闰日、夏令时、超时临界、恰好过期 | 本地时区依赖、时钟回拨 |
| 文件 | 0 字节、超大、类型不符、同名、含路径片段 | 上传失败、目录穿越、解压炸弹 |
| ID / 引用 | 不存在、已删除、属于他人、属于其他租户 | 越权、空引用、级联影响 |

## 2. 业务规则维度

- 首次使用 / 已有数据 / 历史脏数据三种起点；
- 权限边界：未登录、低权限、跨角色、跨租户、管理员；
- 数量边界：单条、批量上限、分页最后一页、无结果；
- 顺序边界：并发到达、重复提交、乱序消息、迟到响应；
- 兼容边界：旧客户端、旧数据、旧配置、旧版本 API。

## 3. 依赖与外部系统维度

| 场景 | 需要明确的期望行为 |
| --- | --- |
| 依赖不可用 / 超时 | 快速失败还是降级；用户看到什么；是否有重试上限 |
| 返回异常数据 | 如何校验；是否写入；如何报警 |
| 部分成功 | 已成功部分是否回滚；如何重放；数据一致性状态 |
| 权限不足 | 拒绝时的错误码与文案；是否泄漏资源存在性 |
| 限流 / 配额耗尽 | 是否可重试；重试间隔；用户提示 |
| 异步任务失败 | 补偿路径、可观测信号、人工介入入口 |

## 4. 数据一致性维度

- 写操作失败后数据处于什么状态；是否留下半成品记录；
- 事务边界跨了哪些资源；跨服务时如何补偿；
- 缓存与数据库不一致的窗口与恢复方式；
- 迁移期间新旧代码/新旧数据并存的行为。

## 5. 安全维度

- 输入校验在服务端完成，不依赖前端；
- 对象级授权逐个资源判定，列表/导出/批量同样适用；
- 错误信息不泄漏堆栈、路径、SQL 或资源存在性以外的信息；
- 日志与审计不记录凭据、完整请求体、个人信息。

## 6. 写法要求

- 每条异常场景都写成「触发条件 → 系统可观察行为 → 是否需要人工介入」；
- 不写「系统应妥善处理」这类无法验收的表述；
- 无法判定期望行为时，把它转成"待用户确认事项"，
  附背景 + 可选路径 + 各自后果。
